# Lumi v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first Windows release of Lumi, an SMTC-based music controller with a glass main window and a low-misclick quick bar.

**Architecture:** Tauri 2 hosts React renderer windows and a Rust backend. Rust owns Windows media sessions, lyrics fetching/caching and native window behavior; React renders the main and quick windows from typed commands and events.

**Tech Stack:** Tauri 2, Rust stable, Windows crate, React 19, TypeScript, Vite, Tailwind CSS, Radix UI, Lucide, Zustand, Vitest, Testing Library, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-11-lumi-design.md`

## Global Constraints

- Windows 10/11 x64 only.
- Support only apps that publish SMTC sessions.
- Never send account, source-app or history data to LRCLIB.
- Quick bar launches locked with pointer events disabled.
- Dark mode is the default; all layouts must work in light mode.
- No continuous GPU animation in the quick bar.

## Review Focus

- A media session disappearing while selected must not crash or retain stale controls.
- A fast track switch must not apply an older lyrics response.
- Locked quick-bar hover must not make the window clickable.
- Imported malformed LRC must fail visibly without breaking playback.
- SMTC manager failures must remain explicit rather than showing fabricated state.
